# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

AlkansyaPH is a personal Philippine stock (PSE) portfolio tracker, built with Expo + React Native + Expo Router. Core loop: open app → see total portfolio value/performance → browse PSE stocks and news → add/adjust holdings → value updates. Real accessory features on top of that loop: daily-refreshed market news, real (not fabricated) push/in-app notifications on large price moves, a display-currency preference, and per-holding purchase dates.

The backend is real, not mocked: Supabase project `zraunfstpbgqbckeaofs` (auth, Postgres with RLS, Edge Functions, `pg_cron`). Per-user data isolation is enforced server-side via RLS policies, not just in the UI — verify this with direct REST calls (spoofed `user_id` should 403), not just by checking the UI, before trusting any change to `holdings` access.

`eas.json` exists (a `preview`/`development` profile both build a plain installable APK via `"buildType": "apk"`) but no EAS *project* is linked yet (no `extra.eas.projectId` in `app.json`) — the app only runs today via Expo Go or `expo start --web`. Getting a real installable APK or working push notifications (Expo Go dropped remote push support) requires `eas init` + `eas build`, neither of which has been run; both need an interactive `eas login` this environment can't complete unattended.

App icon/logo: `assets/images/icon.png` (also used for `favicon.png`, `splash-icon.png`, `android-icon-foreground.png`, and the in-app `AuthMark` component) is the real AlkansyaPH logo (piggy bank + ₱ coin + wordmark), sourced from `logo.png` at the repo root. It has no alpha channel (opaque white background baked in) and isn't safe-zone-cropped for Android's adaptive-icon mask or reduced to a proper monochrome/notification-tray silhouette — `android-icon-monochrome.png` is still the old placeholder. Good enough to ship; revisit with a real icon-generation pass (e.g. `npx expo-icon` or a design tool) if the Android icon looks clipped.

After any dependency-affecting or route-structure change, restart the dev server and re-run `npx tsc --noEmit` + `npm run lint` + `npx expo-doctor` — this project has hit real issues that only show up that way (see Gotchas).

## Architecture

**Routing.** Expo Router, file-based, rooted at `src/app` (SDK auto-detects `src/` as the app root — no metro.config override needed). Path alias `@/*` → `src/*` (see `tsconfig.json`).

- `src/app/_layout.tsx` — root layout. Wraps everything in `ThemePreferenceProvider` → `CurrencyProvider` → `AuthProvider` → `PortfolioProvider`, then gates the whole tree with `Stack.Protected guard={...}`: unauthenticated users only ever see the `(auth)` group; authenticated users see `(tabs)` plus the modal/detail routes below. Also fires push-notification registration once a `user` exists.
- `(auth)/` — `login.tsx`, `signup.tsx`, backed by real Supabase auth (`src/context/auth-context.tsx`). Login remembers the last signed-in email per device (`src/lib/auth-memory.ts`, AsyncStorage) to decide "Welcome" vs "Welcome back" and whether to prefill the email field — don't reintroduce a hardcoded default email.
- `(tabs)/` — the 4 primary surfaces: `index.tsx` (Portfolio/home), `stocks.tsx`, `news.tsx`, `settings.tsx`. Tab bar is a custom-styled `Tabs` from `expo-router` (not `unstable-native-tabs` — that was swapped out early for cross-platform/web styling control).
- `add-holding.tsx`, `edit-holding/[id].tsx`, `change-password.tsx`, `delete-account.tsx` — root-level modals (`presentation: 'modal'`). `edit-holding/[id].tsx` opens read-only with an "Edit Holding" button; the adjust-shares form (quantity field, Save/Cancel/Remove) only renders after that's tapped, on purpose — don't make the quantity field editable by default again. `delete-account.tsx` requires typing a literal `DELETE` confirmation before it'll call `deleteAccount()` — this is genuinely irreversible.
- `stock/[symbol].tsx` — root-level push route (not a modal) for the per-stock detail page (own price graph + index stats + add/update CTA).

**State.** React contexts hold client-side preferences; server state (stocks, holdings, news) goes through React Query instead:
- `AuthProvider` (`src/context/auth-context.tsx`) — real Supabase session (`user`, `isAuthenticated`, `isInitializing`), plus `login`/`signup`/`logout`/`changePassword`/`deleteAccount`. `changePassword` re-verifies the current password via `signInWithPassword` before calling `updateUser`, then calls `signOut({ scope: 'others' })` so every *other* signed-in device is forced to re-authenticate. `deleteAccount` calls the `delete-account` Edge Function then signs out locally. `logout` unregisters this device's push token first. Signup requires an 8+ character password (`MIN_PASSWORD_LENGTH` in `signup.tsx`) and has a hidden honeypot field (`website`) — a filled honeypot fails signup generically without revealing why.
- `PortfolioProvider` (`src/context/portfolio-context.tsx`) — owns `Holding[]` (from `public.holdings`, RLS-scoped to the signed-in user) and derives `holdingsWithMarketData` (joined against live stock data) plus portfolio-wide totals. `addHolding`/`increaseHolding`/`decreaseHolding`/`removeHolding` are the only mutation paths — screens should go through `usePortfolio()`, never mutate holdings directly. Each mutation's final values are precomputed in the wrapper callback (from the hook's own reactive `holdings` state) *before* `mutate()` runs — mutationFn/onMutate must never independently re-derive "existing + delta" from `queryClient.getQueryData()`, since onMutate's optimistic write lands in that same cache before mutationFn executes and a second independent computation there will double-apply the change (this was a real, previously-shipped bug).
- `CurrencyProvider` (`src/context/currency-context.tsx`) — a *display-only* currency preference (PHP/USD/EUR/JPY/SGD), AsyncStorage-persisted. Holdings are always entered and stored in PHP (the only currency PSE stocks trade in); `useMoneyFormat()` (`src/hooks/use-money-format.ts`) converts using live rates from `useExchangeRates()` (`src/hooks/use-exchange-rate.ts`, `api.frankfurter.dev`, 1h staleTime) and is what screens should call instead of importing `formatCurrency`/`formatSignedCurrency`/`formatMarketCap` straight from `utils/format.ts`. Deliberately *not* applied to `add-holding.tsx`'s price input/estimated-cost fields — converting the actual transaction-entry fields would make it ambiguous what currency you're typing.
- `ThemePreferenceProvider` (`src/context/theme-preference-context.tsx`) — resolves `system`/`light`/`dark` preference against the OS scheme (in-memory only, not persisted). `useTheme()` (`src/hooks/use-theme.ts`) is the *only* place color tokens should come from (`Colors.light`/`Colors.dark` in `src/constants/theme.ts`); styles pull colors inline (`{ color: theme.text }`) rather than through wrapper components.

**Data layer (Supabase).** Client at `src/lib/supabase.ts` (SSR-safe storage wrapper — no-ops during Expo Router's Node-based SSR pass, where `window` doesn't exist). Credentials in `.env` (gitignored; `.env.example` is the template). Tables: `public.stocks` (~294 PSE-listed common-equity tickers seeded from phisix; RLS public-read; only the ~30 original PSEi-heavy tickers have `sector`/`float_million`/`market_cap_billion`/`index_weight_percent` hand-curated, the rest are phisix-only and `sector` reads back as `'Uncategorized'` client-side rather than a fabricated PSE classification), `public.holdings` (per-user, RLS via `auth.uid()`, includes `purchased_at` — set once at Add Holding time, never touched by later increase/decrease since there's no per-lot transaction ledger, just one merged position per symbol), `public.stock_price_history` (append-only, written by the scraper — daily bars from a one-time historical backfill plus live ~15-min snapshots going forward), `public.news_articles` (RLS public-read), `public.push_tokens` and `public.price_alerts_sent` (RLS owner-only). No `profiles` table — `name`/`created_at` come straight off `auth.users`.

- `src/hooks/use-stocks.ts` — React Query hook reading `public.stocks`, `getStockBySymbol()` lookup.
- `src/hooks/use-news.ts` — reads `public.news_articles`, synced daily from PH business RSS feeds (`supabase/functions/sync-news`).
- Live prices: `supabase/functions/sync-stock-quotes` (phisix API, not PSE Edge — `edge.pse.com.ph`'s robots.txt disallows `ClaudeBot`), scheduled via `pg_cron` during PSE market hours, gated by `src/utils/market-hours.ts`'s `isPseMarketOpen()` logic re-implemented server-side. **phisix does not provide true intraday ticks** — verified that every tracked symbol reports the identical price on every ~15-min poll within a trading day (a settlement/reference price, not tick-level trades), so the 1D chart range will typically render flat regardless of symbol; that's the data source, not a bug.
- Price alerts: `supabase/functions/send-price-alerts`, scheduled 2 min after each `sync-stock-quotes` tick, pushes to any user holding a stock that moved ±5% today (deduped per user/symbol/day via `price_alerts_sent`), via Expo's push API. Client registration in `src/lib/notifications.ts`, gated on `Device.isDevice` and an EAS `projectId` being present — silently no-ops otherwise (see "What this is").
- **`sync-stock-quotes`, `sync-news`, and `send-price-alerts` are internal/cron-only** — deployed with `verify_jwt: false` and their own check instead (`isAuthorizedInternalCaller` in each function, duplicated per-file since Edge Functions deploy independently): a constant-time comparison against a secret fetched via `public.get_internal_secret()`, a `SECURITY DEFINER` RPC restricted to `service_role` that bridges to `vault.decrypted_secrets` (Vault isn't exposed via PostgREST directly). `verify_jwt: true` alone isn't sufficient here since it accepts *any* valid Supabase JWT, including the public anon key that ships in the app bundle — these functions used to (wrongly) accept that. pg_cron sends the real secret (Vault entry `internal_cron_secret`) as the bearer token. If you add a new internal-only function, follow this pattern rather than relying on `verify_jwt` alone.
- `supabase/functions/delete-account` — the one Edge Function that *should* stay `verify_jwt: true` (any signed-in user may call it) — deletes the caller's own account via `auth.admin.deleteUser`, id always taken from their own verified JWT (`auth.getUser()`), never from a request body field. Cascades to `holdings`/`push_tokens`/`price_alerts_sent` via their FKs.
- `supabase/functions/scrape-pse` is a retired stub (kept because there's no MCP/CLI call to delete an Edge Function) — do not resurrect PSE-Edge scraping, it's robots.txt-disallowed for Claude specifically.
- There is no PSEi composite index value anywhere in the app (no free/legitimate live source was ever found) — don't add one back without a real data source.
- Schema changes are applied directly to the live project and mirrored as timestamped files in `supabase/migrations/` for history — when adding a migration, do both (apply it for real, and write the matching local file) rather than just one.

**Charts** are hand-rolled SVG (`src/components/performance-graph.tsx`, via `react-native-svg`) — a smoothed line + gradient-fill area, plus optional min/max value labels via a `formatValue`/`labelColor` prop (pass the caller's `useMoneyFormat().formatCurrency`, not the raw util). Two hooks feed it, both returning `{ range, setRange, points, changeAmount, changePercent, isPositive, isLoading }`:
- `src/hooks/use-stock-history.ts` — a single symbol's real price history from `stock_price_history`. `1D` is a distinct code path (raw intraday rows, no day-bucketing) from `1W`/`1M`/`3M`/`1Y` (one point per calendar day).
- `src/hooks/use-portfolio-history.ts` — portfolio value history. There's no transaction/quantity-history ledger in this app, so this approximates historical value as *current* holding quantities × historical price per symbol, forward-filling gaps. Two things this deliberately does *not* do naively: (1) it clamps the visible range to the earliest `purchasedAt` across current holdings, so a 1Y view for a position bought last month shows one month, not a fabricated year; (2) each holding only contributes to the total from its own `purchasedAt` onward, so adding a second position partway through the visible window shows a real step up in the line. `1D` again has its own intraday code path, aligning symbols by their exact shared `captured_at` (every symbol in one `sync-stock-quotes` run shares the same timestamp).

**Notifications.** The bell panel (`src/components/screen-header.tsx`) computes each holding's real daily % move from `usePortfolio()` — no static/hardcoded list. Push delivery is the `send-price-alerts` pipeline above; see "What this is" for why it can't be tested end-to-end yet.

**Component layout:** `src/components/ui/` = generic, content-agnostic primitives (`primary-button`, `avatar-badge`, `change-pill`, `detail-grid`, `search-bar`, `segmented-control`, `market-status-badge`, `text-field`, `section-header`, `screen-container`). `src/components/` (flat) = feature-specific composites that know about stocks/holdings/news (`holding-row`, `stock-row`, `news-card`, `performance-card`, `performance-graph`, `portfolio-hero`, `screen-header`, `auth-mark`). New reusable, domain-agnostic UI goes in `ui/`; anything that imports from `@/lib` or `@/context` goes flat.

**Formatting:** currency/market-cap values go through `useMoneyFormat()` (see State/CurrencyProvider above), not `src/utils/format.ts` directly, except in `add-holding.tsx`'s transaction-entry fields. Non-currency formatters (`formatSignedPercent`, `formatShares`, `formatNumber`, `formatDate`, `formatRelativeDate`, `formatSignedPoints`) still live in and should be called from `utils/format.ts`. The ₱ currency formatting has a real rendering gotcha (see below).

**Market hours:** `src/utils/market-hours.ts` (`isPseMarketOpen`) computes real PSE trading hours (Mon–Fri, 9:30 AM–3:30 PM) in the `Asia/Manila` timezone specifically, independent of device timezone. `useMarketStatus()` polls it every 30s; `MarketStatusBadge` is the UI. Does not account for PH market holidays.

## Gotchas

- **Pinned to Expo SDK 54** (`react` 19.1.0, `react-native` 0.81.5) — intentionally, because the team's Expo Go app only supports up to SDK 54. Don't bump `expo`/`react`/`react-native`/`react-native-*` without checking that constraint first; if you do, use `npx expo install --fix` afterward, not manual version bumps.
- **Route types can go stale.** `.expo/types/router.d.ts` is generated and gitignored. Adding a new route directory has, at least once, produced bogus `Href` types (phantom routes pointing at `../components/...` etc.) until the dev server was restarted. If `tsc` complains about a `router.push()` path that clearly exists as a file under `src/app/`, delete `.expo/types/router.d.ts` and restart `npm start`.
- **`expo-env.d.ts` must exist** for `tsc` to know about `*.css` imports and CSS-module types (it's generated by Expo CLI on first run / gitignored). If it's missing, `tsc` fails on `@/global.css` and `.module.css` imports with `Cannot find module` errors — recreate it with a single line: `/// <reference types="expo/types" />`.
- **Never use `fontWeight: '800'` or `'900'`.** On Chrome/Windows (Segoe UI), those weights aren't natively available and get synthetically bolded, which visibly corrupts the ₱ (peso sign, U+20B1) glyph so it overlaps the next character. Confirmed via screenshot diffing — `'700'` is the max safe weight app-wide.
- **Use `boxShadow` (string or array), not `shadowColor`/`shadowOffset`/`shadowOpacity`/`shadowRadius`** — the legacy shadow props are deprecated under React Native Web on this RN version and log console warnings.
- **`react-native-worklets` is a separate dependency from `react-native-reanimated`** at this SDK/version — both are pinned explicitly in `package.json`; don't remove one assuming the other bundles it.
- **"Uncommitted Shares"** on the holding-details grid is always equal to Total Shares — there's no order/execution system in this app, so nothing is ever actually "committed" to a pending order. That's a deliberate simplification reflecting product scope, not a bug to fix.
- React Compiler is enabled (`app.json` → `experiments.reactCompiler`), so manual `useMemo`/`useCallback` are a style choice, not strictly required for new code — but plenty of existing code uses them explicitly and there's no push to remove them.

## Testing changes

There's no automated test suite. The established way to verify UI changes in this repo (used throughout its history) is: `npx tsc --noEmit` + `npm run lint` + `npx expo-doctor`, then actually run the dev server and drive it in a real browser (Chrome, via Playwright against `http://localhost:8081`) or Expo Go — screenshot and check for console/page errors rather than assuming a change "should work." For anything touching `holdings` RLS specifically, also verify with direct REST calls (not just the UI) that a spoofed `user_id` gets rejected.
